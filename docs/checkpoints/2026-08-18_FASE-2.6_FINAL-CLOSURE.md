### B. Ricevute Firmate Ed25519 e Modello Crittografico V2
* Verifica crittografica asimmetrica Ed25519 con serializzazione canonica deterministica JSON (`canonicalizeJson`).
* Supporto al documento di ricevuta firmata (`ReceiptDocumentV1`) emesso dal server con timestamp certificato e finestra di validità.
* Incapsulamento delle richieste e risposte nei formati envelope conformi allo standard dello Shared SDK (`ActivationRequestEnvelopeV1`, `LicenseValidationResponseEnvelopeV1`, `LicenseDeactivationResponseEnvelopeV1`).

### C. Ciclo Completo del Licensing e Logica Offline-First
* **Ciclo di vita:** Attivazione (`activate`) → Persistenza locale → Validazione online (`validate`) → Validazione offline automatica (`analyzeLocalLicenseOffline`) → Riavvio applicazione → Disattivazione (`deactivate`).
* **Gestione Finestra Offline (Sliding Window):** Calcolo e aggiornamento di `offlineValidUntil` in base alla policy di licenza ricevuta.
* **Tolleranza di Rete:** In assenza di connettività o con server non raggiungibile, la licenza valida mantiene la piena operatività fino al termine della finestra offline (`OFFLINE_VALID_UNTIL_EXPIRED`).
* **Meccanismo Fail-Closed:** Blocco immediato e deterministico in caso di manomissione della firma, alterazione payload, disallineamento `deviceId` (`DEVICE_MISMATCH`) o clock rollback retroattivo.
* **Disattivazione Offline:** Transizione sicura nello stato `DEACTIVATION_PENDING_CONFIRMATION` per garantire la disattivazione immediata sul client con sincronizzazione successiva.

### D. Persistenza Locale e UI Reattiva
* **Persistenza:** Memorizzazione sicura in IndexedDB tramite Dexie (`localLicenseRepository`).
* **Unica Fonte di Verità & Reattività:** `LicenseContext` e hook `useLicense()` integrati con `useLiveQuery` per aggiornamento istantaneo dell'interfaccia utente.
* **Compatibilità Legacy:** Sincronizzazione atomica con il layer preesistente senza dualismo di stato.
* **Interfaccia Utente (`/settings`):** Componente `LicenseSettingsCard.tsx` con visualizzazione badge di stato, mascheramento credenziali sensibili (`maskLicenseCode`, `maskDeviceId`), azione di verifica manuale immediata e modale di conferma per la disattivazione.

### E. Allineamento CI, Node.js e Quality Gate
* Aggiornamento del workflow CI (`.github/workflows/ci.yml`) ad `actions/checkout@v5`, `actions/setup-node@v5`, e runtime `node-version: 22`.
* Verifica checksum del TGZ locale eseguita prima di `npm ci`.
* Pipeline di validazione completa: `npm ci` → `npm run typecheck` → `npm run lint` → `npm test` → `npm run build`.
